3 Règles de matching — par niveau de fiabilité
🔑 NIVEAU 1 — Référence facture (col D encaissement → col O impayés)
La clé primaire. Extraite par REGEXEXTRACT dans Google Sheets ou annotée manuellement en col D.
SEM : pattern 10\d{12} (14 chiffres commençant par 10)
SEMM : pattern 40\d{12} (14 chiffres commençant par 40)
EFICASH : ref 40xxx dans le libellé après REF: 00
Résultat : 26/27 SEM ✓ • 105/118 SEMM ✓ • 4/4 EFICASH ✓
🔑 NIVEAU 2 — N° de Contrat (col D encaissement → col C impayés)
Quand col D contient un numéro 5-7 chiffres. Ou extrait du libellé via contrat NNNNNNN.
⚠️ Padding zéros : Le contrat dans les impayés fait 7 caractères avec zéros en tête. Padder 447068 → 0447068.
Résultat : 6 SEM ✓ • 27 SEMM ✓ (26 matchent après padding)
🔑 NIVEAU 3 — Nom + Montant (libellé B → col J + col T impayés)
Extraction du nom après "VIREMENT DE" ou "VIREMENT INSTANTANE DE" + comparaison avec Solde TTC.
Fiabilité : Moyenne — noms souvent tronqués (25 car. max dans libellé bancaire).
🔑 NIVEAU 4 — Recherche cross-société
Certains payeurs versent sur un compte SEMM pour des factures SEM (ref 10xxx) ou VIVAIGO (ref 33xxx).
Ex : GARIG SAS (SEMM) paye la ref 10251100001745 (SEM) • SDC NOTRE DAME (SEMM) pour ref 33251200016918 (VIVAIGO).
Règle : Toujours chercher dans TOUT l'index des refs, pas seulement la société du fichier.
4 Cas spéciaux et pièges identifiés

Sous-lignes de ventilation (D/E sans B)

Un organisme (AJAssocies, SDC...) paye un montant global pour N contrats. Les lignes suivantes (sans libellé) détaillent chaque ref (D) et montant (E).

23 sous-lignes dans SEMM. La somme des E ≈ montant C (delta arrondi ≤ 0,12 €).

Règle : Chaque sous-ligne = un match individuel D→col O.

Références tronquées (13 chiffres)

Certaines refs en col D font 13 au lieu de 14 chiffres (dernier chiffre coupé). Ex: 1025110000433, 40251000001810.

Cause : Troncature dans le libellé bancaire (limite 105 caractères) ou extraction regex incomplète.

Règle : Si ref fait 13 chiffres → match par préfixe dans l'index des refs.

Paiement cross-société / multi-société

Libellés contenant "REGLEMENT SEMM / SEM / APE / SAE / SAOM" = virements regroupés pour plusieurs sociétés.

~5 lignes concernées (Row 75, 134, 153...). Montant global non ventilé.

Règle : Marquage "ventilation manuelle requise".

SGC / GC (Service Gestion Comptable)

Les refs sont collées dans le texte sans espace. Ex: 4025100000410DU 30/04... contient 4025100000410 (13 chiffres).

Règle : Regex élargie r'(40\d{11,13})' pour capter les refs collées.

SAGE (travaux / maintenance)

9 lignes SEM avec annotation SAGE. Refs type 72-AIX2512-0015. Ce sont des factures travaux (pas eau) qui ne sont pas dans le fichier impayés.

Règle : Circuit de traitement séparé (Sage ↔ comptabilité).

INTRUM (recouvrement)

Paiements globaux sans détail de ref. "INTRUM VERSEMENT DU 20251212".

Règle : Marquage "recouvrement INTRUM — ventilation manuelle".

6 Algorithme de rapprochement
// PRÉPARATION
1. Charger impayés → index_par_ref[col_O] + index_par_contrat[col_C.zfill(7)]
2. Charger encaissements SEM + SEMM → filtrer vides, éclater sous-lignes
3. Exclure: TOTAL, montant négatif

// POUR CHAQUE LIGNE D'ENCAISSEMENT
NIVEAU 1 — Match par Référence
  a) Col D = pattern 10/40/33 + 12 chiffres (14 total) ?
     → lookup exact dans index_par_ref
     → si trouvé: MATCH_REF + vérifier montant C ≈ Solde T
  b) Col D = EFICASH ? → extraire ref du libellé via REF: 00(40xxx)
  c) Col D = GC/vide ? → extraire ref(s) du libellé B (regex élargie 11-13 chiffres)
  d) Ref fait 13 chiffres ? → match par PRÉFIXE (LIKE 'ref%') dans index

NIVEAU 2 — Match par Contrat
  a) Col D = 5-7 chiffres ? → padder à 7 avec zfill → lookup index_par_contrat
  b) Extraire contrat du libellé B → même lookup
  c) Si multi-match → départager par montant C vs Solde T le plus proche

NIVEAU 3 — Match par Nom + Montant
  a) Extraire nom du libellé B (après "VIREMENT DE")
  b) Fuzzy match sur col J des impayés (threshold > 80%)
  c) Confirmer par montant C ≈ Solde T (tolérance ±0.5%)
  → MATCH_PROBABLE (flag pour validation)

NIVEAU 4 — Non rapproché
  → Catégoriser: INTRUM | CROSS-SOCIETE | NOM_SEUL | INCONNU
  → Marquer pour traitement manuel

9 Recommandations techniques
  1. Formules REGEXEXTRACT : Proviennent de Google Sheets (__xludf.DUMMYFUNCTION). En Python : lire avec data_only=True pour les valeurs cached, OU ré-appliquer la regex sur le libellé.
  2. Index performant : Charger les 112K lignes d'impayés en dictionnaires Python (ref→infos, contrat→infos) pour des lookups O(1).
  3. Types string obligatoires : Lire col C (contrat), col E (client), col O (ref) en dtype=str pour conserver les zéros en tête.
  4. Tolérance montant : Accepter un delta ≤ 0,02 € sur les montants (arrondis centimes).
  5. Multi-match ref : Si une ref a plusieurs lignes dans les impayés (ex: FC + FR), prendre celle dont le Type R = FR (facture relève) et le Solde TTC > 0.
  6. Fichier d'import : La cible finale est de générer le fichier d'import Waterp pour supprimer la saisie manuelle des ~250 lignes quotidiennes.
